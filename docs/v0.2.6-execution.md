## 已实现

- Web 与 APP 的组织、人脉详情接入管理表单；手机单列排版。
- 组织基础字段和上级组织可修改；既有循环层级与下级删除保护继续生效。
- 人脉基础资料、标签可修改；任职关系可新增、编辑、设为主要、转历史、删除误录。
- 待办标题、说明、截止时间、优先级、状态可修改；独立待办可调整关联与内部事项标记。来源待办保留来源和原关联，不提供改关联入口。
- 拜访沿用既有编辑表单，新增记录删除入口。
- 记录删除只开放给管理员、经理，沿用软删除；不级联删除其他事项、组织、人脉。删除人脉会软删除其任职；删除事项沿用附件清理触发器。
- 管理表单读取最新详情，按字段差异提交，保留未改动的隐藏字段；负责人及人脉可见性暂保持只读，不开放转交入口。
- 组织、人脉写入/删除支持 If-Match 版本检查；任职修改锁定所属人脉并推进版本，避免主要任职并发写入。
- 待办编辑及完成/恢复携带 expectedRevision；事项删除在事务内复核版本和是否已删除。
- 任职日期有效性及先后顺序检查；历史任职不能保留主要标记。
- 冲突/失败保留输入；保存后刷新主列表与统计；未保存返回确认、请求处理中防重复和防关闭。
- 档案存在未保存修改时，阻止打开任职编辑及删除任职，避免重新载入详情覆盖输入。
- CORS 增加 If-Match；无需数据库结构迁移。

先运行 `npm run build`，另一个终端运行 `node tests/ui-harness.cjs`，随后执行 `node tests/record-maintenance-browser.cjs`（需要 Playwright，可设置 `QA_PLAYWRIGHT_PATH`）。测试服务仅监听 `127.0.0.1:18189`。

模拟器脚本必须配合 QA 服务地址构建和明确的 `emulator-5580` WebView 转发，脚本会检查 AVD 名称；不可将设备序列号改为真实手机。
