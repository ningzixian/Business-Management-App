# 第五阶段修复记录

范围：I16 弹窗和返回、I17 通知、I21 六尺寸布局。沿用 v0.2.0 的 23 项分阶段修复计划；不发布正式系统或新 APK。

## 实施

### I16 弹窗、键盘和返回

- 新建/编辑表单、账号弹窗、通用详情、拜访抽屉、地图确认和手机菜单使用统一 DialogLayer。
- Tab/Shift+Tab 在当前顶层弹窗内循环；Esc 只关闭顶层；嵌套详情关闭后恢复原触发按钮焦点，背景页面不滚动。
- 修改输入后，关闭、取消、遮罩、切换记录类型、Esc 和返回均需要放弃修改确认；拒绝后保留表单。页面刷新/离开另使用浏览器 beforeunload 提示，是否显示由浏览器控制。
- 表单提交及附件处理中暂不允许关闭，提示等待结果。附件文件选择器在处理中禁用。
- 弹窗开启时暂缓跨断点的组件切换，避免旋转屏幕或改变窗口宽度导致页面所属表单被卸载；关闭后再应用新布局。
- 浏览器返回通过临时历史记录关闭弹窗；Android 使用原生 Back 回调进入同一关闭逻辑，无弹窗时先关闭通知/菜单或回工作台，工作台再返回则转入后台。
- 原生 Java 编译通过；真实 Android 系统返回、输入法、文件选择器和后台恢复仍属于第六阶段新 APK 真机验证，不把浏览器事件模拟当成真机通过。

### I17 通知

- 移除“刚刚”“双库同步正常”等固定示例。当前通知明确限定为当前部门的真实逾期待办，不含系统推送、短信或虚构业务事件。
- 新增 notifications 接口及 005_notification_reads.sql；已读键为用户与事项，绑定当前登录部门验证，不接受客户端指定其他用户。
- 通知列表和红点使用同一份数据；单条和全部已读成功后重新查询。只读用户可处理自己的已读状态，不改变业务事项。
- 已读状态保存在数据库，可跨刷新、重新登录和设备读取；调整截止时间形成新提醒，完成/取消/删除事项后不再显示。相同截止时间重开的事项沿用此前已读状态。
- 点击通知请求对应真实待办详情，显示说明、来源和附件；加载失败明确提示，不跳转到无关页面。保存已读失败保留红点并允许重试。
- 每分钟、回到窗口、新增/修改待办和打开通知时刷新；支持点击外部关闭、Esc 关闭并恢复通知按钮焦点。通知不是实时推送，其他用户的变化可能存在最多约一分钟的刷新延迟。

### I21 六尺寸布局

- 手机页面和外壳统一采用 max-width: 980px，补齐原 721–980 区间的菜单入口。
- 390/720/721/980 保留手机工作台与底部导航，完整菜单可进入日历/统计/设置；981/1440 使用桌面侧边栏。

- 保持稳健企业蓝及既有手机专用页面，不更换前后端架构。
