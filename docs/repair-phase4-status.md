# 第四阶段修复记录

范围：I08 附件闭环、I09 手机既有按钮。沿用 v0.2.0 分阶段修复计划；未实施通知、弹窗键盘/返回、多尺寸断点及正式发布。

## 实施

### I08 附件

- 拜访详情、Web 待办详情、手机待办“更多”及日历待办详情共用附件面板，支持列表、上传、刷新、下载、确认删除。
- 先保存事项，再上传附件，避免未建档文件没有归属。新建表单的拍照/录音入口明确禁用并说明保存后上传，不再声称未来版本会提供当前已接入的附件能力。
- 支持 JPEG/PNG/GIF/WebP/HEIC/HEIF、Office/PDF、文本/CSV、常见音频文件。拒绝 SVG、HTML 和可执行 MIME 类型；不宣称有病毒扫描或内容真实性检测。录音指上传已有文件，不包含在线录音、语音识别或转写。
- 每次单文件，默认最大 20 MB；前端和服务端均校验空文件、大小及支持格式。Nginx 请求上限 21 MB，为 20 MB 文件的 multipart 封装留余量。
- 上传/下载显示处理中并锁定重复操作；离开详情中止客户端请求。失败保留事项，提示刷新附件列表核实后再重试，避免超时后重复上传。
- 下载通过认证请求获取二进制，不把令牌放进 URL；校验长度，支持 WebCrypto 的 HTTPS/localhost 环境另校验 SHA-256。普通内网 HTTP 浏览器可能不提供 WebCrypto，不把此场景写成已完成客户端哈希校验。响应强制 attachment、nosniff、private/no-store。
- 安卓新增 `AttachmentFiles` 原生保存桥，使用系统文件保存器选择位置，并在写入前检查 SHA-256；无需新增广泛文件访问权限。旧 APK 无桥时明确提示升级/改用手机浏览器，不虚报已保存。原生 Java 离线编译通过；系统保存器取消、低空间及真机往返留待第六阶段安装包验收。
- 新增迁移 `004_attachment_cleanup.sql`：持久化清理任务表、到期索引及事项删除触发器。上传前登记 1 小时清理租约；元数据和审计成功提交时移除任务；失败或进程中断仍保留任务。删除立即取消业务访问，并在同一事务登记清理任务。
- 清理每分钟执行，每批最多 20 项；删除失败增加尝试次数并延迟 5 分钟，重启后继续。有效附件元数据优先，绝不因残留清理任务误删有效文件。删除事项时，其附件一并取消访问并排队清理。不盲扫、不全量删除对象存储中无登记的历史文件。

### I09 手机按钮

| 入口 | 实际行为 |
| --- | --- |
| 工作台联系客户/导航到访 | 完整电话进入拨号；地址经确认后打开高德搜索，明确需要公网且会发送地址 |
| 组织打电话/导航 | 使用有效电话和组织详细 address，不拿地区冒充地址；缺失时禁用并显示原因 |
| 人脉联系、拜访列表联系/导航 | 使用同一电话校验和外部地图确认逻辑 |
| 待办更多 | 打开真实待办详情、说明、来源和附件 |
| 设置内网服务/APP 信息 | 显示连接说明、版本与安装包区别，不再空操作 |
| 新建拜访拍照/录音 | 明确提示先保存后到详情上传，在线录音转写不在本轮范围 |

保留其余已正常工作的创建、筛选、日期切换、来源跳转和账号操作；AST 测试逐一扫描相关手机 JSX 按钮，要求有动作、提交语义或明确禁用状态。
